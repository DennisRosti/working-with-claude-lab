# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

Two things at once: a Claude Code workshop (`workshop/`, `docs/`) and the sample app the labs run against, **ops-dashboard** — a Spring Boot REST API over PostgreSQL plus a plain-JavaScript wall-screen page for Marlowe & Finch's operations office. Tickets live in `docs/tickets/` (TODO-231 theme toggle, TODO-232 input validation, TODO-233). When a ticket file and a chat instruction disagree, the ticket wins — say so.

## Commands

```bash
# Run (needs Docker for PostgreSQL)
docker compose up -d db          # PostgreSQL 16 on :5432, db/user/password "ops"
./mvnw spring-boot:run           # http://localhost:8080

# Run without Docker / in Claude Code on the web: in-memory H2, same migrations and seed
SPRING_PROFILES_ACTIVE=demo ./mvnw spring-boot:run

# Tests (neither suite needs a database; Java tests use the demo/H2 profile)
./mvnw test                                        # JUnit 5 + MockMvc, expect 25 tests
./mvnw test -Dtest=DashboardRepositoryTest         # one class
./mvnw test -Dtest=DashboardRepositoryTest#method  # one method
npm install                                        # once
npm test                                           # Jest + jsdom, expect 45 tests
npx jest src/test/javascript/render.test.js        # one file
npx jest -t "asks for at most 20"                  # by test name

# Regenerate seed SQL, CSV and the git-ignored docs/data/ANSWER-KEY.md (deterministic)
python3 tools/make_seed.py
```

There is no linter or frontend build step. CI is not enabled; `docs/examples/ci.workflow.yml` is a template to copy into `.github/workflows/`.

## Definition of done

- Run both `./mvnw test` and `npm test` and report both counts.
- Register any new element `id` added to `index.html` in `REGISTERED_IDS` in `src/test/javascript/setup/loadApp.js` — `harness.test.js` fails otherwise.
- Restart the app so the change can be clicked at http://localhost:8080.

## Constraints

- **`pom.xml` dependencies are frozen** (changes require a CHG ticket). Don't add or change dependencies; a workshop hook (`docs/examples/hooks/pom-guard.sh`) enforces it.
- No JPA, no frontend framework, no new npm/Maven dependencies. Charts are hand-built inline SVG.
- SQL in migrations and repositories must run unchanged on both PostgreSQL 16 and H2 in PostgreSQL mode.

## Architecture

**"Today" is pinned to 2026-09-21.** `ops.today` in `application.properties` → `Clock` bean in `ClockConfig`. Never use `LocalDate.now()` without the injected `Clock`. All default ranges are "last 30 days ending today" (`DateRange.resolve`). The frontend doesn't use the browser date either: it calls `/api/health` first and takes `today` from the response, then fires the range endpoints. Seed data covers the 90 days before that date, and test expectations are exact figures from that seed.

**Backend** (`src/main/java/com/marlowefinch/ops/`): thin `@RestController`s take optional `from`/`to` strings, call `DateRange.resolve(from, to, clock)`, and delegate to `DashboardRepository` / `VendorRepository`, which run plain SQL via `NamedParameterJdbcTemplate` and map rows to Java `record` response types. Counting conventions (documented on `DashboardRepository`, shared with the seed and answer key): deliveries by `delivered_date` (in-transit excluded), on time means `delivered_date <= promised_date`, orders by `ordered_at`, revenue excludes cancelled orders, tickets by `opened_at`. There is intentionally no input validation yet (bad date → 500, `from > to` → empty, any `limit`) — that's TODO-232.

**Database**: Flyway migrations in `src/main/resources/db/migration/` (`V1__schema.sql`, `V2__seed.sql`). `V2__seed.sql` is generated by `tools/make_seed.py` — edit the generator, not the SQL. Profiles: `postgres` (default, overridable via `DATABASE_URL`/`DATABASE_USER`/`DATABASE_PASSWORD`) and `demo` (H2).

**Frontend** (`src/main/resources/static/`): `app.js` is a single IIFE exposing `initApp(document, fetchImpl)` plus pure helpers (`formatRate`, `formatMoney`, `barWidths`, `applyPreset`, `daysUntil`). Under Node it exports via `module.exports`; in the browser it attaches `window.OpsDashboard` and starts on `DOMContentLoaded`. Keep this dual-mode shape so Jest can load it.

**Frontend test harness** (`src/test/javascript/setup/loadApp.js`): `loadApp(overrides)` injects `index.html`'s body into jsdom, replaces `fetch` with an in-memory fake of every `/api` endpoint (fixtures in `FIXTURES`, override by name, or `failing: ['/api/kpis']` to force 500s), requires `app.js` fresh, and awaits `app.ready`. A new API endpoint used by the frontend needs a case in `createFakeApi`.

**Postgres MCP**: `.mcp.json` registers a read-only `postgres` MCP server against the local compose DB. Without Docker, `docs/data/deliveries-last-30-days.csv` answers the same questions.
